The first list is where non-custodial **card services** are available; SEPA and ACH bank-account availability is listed per country. Source: the Supported Countries and Bank Account Availability pages of the Wirex docs.

## Checking Availability Programmatically

Use the capabilities endpoint to check what a specific user can access based on their country of residence:

```
GET /api/v2/user
```

The response includes a `capabilities` array, for example:

```json
{
  "capabilities": [
    { "type": "SepaAccount", "status": "Active" },
    { "type": "AchAccount", "status": "Active" }
  ]
}
```

Capability types referenced in the docs include `SepaAccount`, `AchAccount` and `CardTopup`.

Status values:

- `Active` -- Available and ready to use
- `NotFulfilled` -- User needs to complete additional verification
- `NotAvailable` -- Not available for the user's country of residence
- `ActivationNotStarted`, `InProgress`, `ExternalProviderVerificationRequired`, `ExternalProviderRegistrationPending` -- seen on `SepaAccount` during activation

### SEPA Activation

Completing verification no longer provisions an IBAN on its own. Branch on the `SepaAccount` status:

| Capability status | Path |
|---|---|
| `ActivationNotStarted` | `POST /api/v1/bank/accounts` with `account_type: "Sepa"` |
| `ExternalProviderVerificationRequired` | `POST /api/v1/bank/accounts/init` -> sign the challenge -> `POST /api/v1/bank/accounts/complete` |
| `ExternalProviderRegistrationPending` | Wait and re-check |
| `InProgress` | Activation already requested; wait for the bank account webhook |
| `Active` | Already provisioned; retrieve details |

Source: the SEPA Account Activation changelog entry.
